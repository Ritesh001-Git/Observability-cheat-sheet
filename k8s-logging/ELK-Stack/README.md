# ELK Stack (Elasticsearch, Logstash, Kibana) with Filebeat

The **ELK Stack** is used for collecting, processing, storing,
searching, and visualizing logs from applications running in Kubernetes.

The stack consists of:

-   **Elasticsearch** -- Stores and indexes logs.
-   **Logstash** -- Processes, filters, transforms, and routes logs.
-   **Kibana** -- Provides a web interface for searching, analyzing, and
    visualizing logs.
-   **Filebeat** -- Lightweight log shipper that collects logs from
    Kubernetes nodes and sends them to Logstash.

## Components

### Elasticsearch

Elasticsearch is a distributed search and analytics engine that stores
and indexes logs.

It receives processed logs from Logstash and makes them searchable.
Elasticsearch allows logs to be retrieved and analyzed efficiently based
on fields such as:

-   Timestamp
-   Namespace
-   Pod name
-   Container name
-   Log level
-   Message
-   Kubernetes labels

### Filebeat

Filebeat is a lightweight log shipper provided by Elastic.

In Kubernetes, Filebeat typically runs as a **DaemonSet**, which means a
Filebeat Pod runs on every Kubernetes node.

Filebeat:

-   Reads container log files from the Kubernetes nodes.
-   Collects logs generated by application containers.
-   Adds Kubernetes metadata.
-   Forwards logs to Logstash.
-   Provides a lightweight alternative to running a heavier
    log-processing agent on every node.

Typical Kubernetes container logs are available under:

``` text
/var/log/containers/
```

Filebeat acts as the first stage of the ELK logging pipeline.

### Logstash

Logstash is a server-side data processing pipeline.

It receives logs from Filebeat and processes them before sending them to
Elasticsearch.

Logstash can:

-   Parse log messages.
-   Filter unwanted logs.
-   Transform log data.
-   Extract fields from log messages.
-   Add or modify metadata.
-   Route logs to different destinations.
-   Send processed logs to Elasticsearch.

A typical Logstash pipeline consists of:

``` text
Input → Filter → Output
```

For example:

``` text
Filebeat
   │
   ▼
Logstash Input
   │
   ▼
Log Processing / Filtering
   │
   ▼
Elasticsearch Output
```

### Kibana

Kibana is a visualization and monitoring interface that connects to
Elasticsearch.

It provides a web interface where users can:

-   Search logs
-   Filter logs
-   View application errors
-   Analyze log patterns
-   Create visualizations
-   Build dashboards
-   Monitor application behavior

Kibana does not normally store the logs itself. It queries Elasticsearch
and displays the data stored there.

# How Everything Works Together

## 1. Kubernetes Pods

Applications run inside Kubernetes Pods.

As applications execute, they generate logs such as:

``` text
INFO Application started
INFO User request received
WARN Database response is slow
ERROR Database connection failed
```

These container logs are written to log files on the Kubernetes node.

A common location is:

``` text
/var/log/containers/
```

## 2. Filebeat Collects Logs

Filebeat runs as a **DaemonSet** in the Kubernetes cluster.

Because it is a DaemonSet, Kubernetes schedules a Filebeat instance on
each node.

Filebeat reads the container log files from the node and collects the
logs.

It can also add Kubernetes metadata such as:

-   Namespace
-   Pod name
-   Container name
-   Node name
-   Container ID
-   Kubernetes labels

Example:

``` text
Application Log
      +
Kubernetes Metadata
      ↓
Filebeat Event
```

Filebeat then forwards these events to Logstash.

## 3. Logstash Processes the Logs

Logstash receives the logs from Filebeat.

It processes the incoming events using a pipeline.

The pipeline generally follows:

``` text
Input
  ↓
Filter
  ↓
Output
```

For example:

``` text
Filebeat
   ↓
Logstash Input
   ↓
Parse JSON
   ↓
Extract log level
   ↓
Add / Modify Fields
   ↓
Send to Elasticsearch
```

Logstash can be used to transform raw application logs into structured
data.

For example:

``` text
Raw Log:

2026-09-20 ERROR Database connection failed
```

can be transformed into structured fields such as:

``` text
timestamp: 2026-09-20
level: ERROR
message: Database connection failed
```

## 4. Elasticsearch Stores the Logs

After Logstash processes the logs, it sends them to Elasticsearch.

Elasticsearch:

-   Stores the logs.
-   Indexes the logs.
-   Makes logs searchable.
-   Allows filtering based on individual fields.
-   Supports large-scale log analysis.

For example, you can search for:

``` text
level: ERROR
```

or:

``` text
namespace: production
```

or:

``` text
pod.name: backend
```

## 5. Kibana Visualizes the Logs

Kibana connects to Elasticsearch.

Kibana queries Elasticsearch and displays the results through its web
interface.

You can use Kibana to:

-   Search logs
-   Filter logs
-   Find application errors
-   Analyze log frequency
-   Create visualizations
-   Create dashboards
-   Monitor application activity

For example, a Kibana dashboard could display:

``` text
Total Logs
     │
     ├── INFO
     ├── WARN
     └── ERROR
```

# Filebeat vs Fluent Bit

Both Filebeat and Fluent Bit can be used as log collectors in
Kubernetes.

### Filebeat

``` text
Kubernetes
    │
    ▼
Filebeat
    │
    ▼
Logstash
    │
    ▼
Elasticsearch
    │
    ▼
Kibana
```

### Fluent Bit

``` text
Kubernetes
    │
    ▼
Fluent Bit
    │
    ▼
Elasticsearch
    │
    ▼
Kibana
```

The key architectural difference is that the **ELK pipeline commonly
uses Logstash for additional log processing**, while an EFK pipeline
commonly uses **Fluent Bit as the collector and processor before
Elasticsearch**.

# ELK Stack in Kubernetes

For a local Kubernetes environment such as **Kind**, the architecture
can be deployed as:

``` text
Kind Cluster
│
├── Application Pods
│       │
│       └── Container Logs
│
├── Filebeat
│       │
│       └── DaemonSet
│
├── Logstash
│       │
│       └── Deployment
│
├── Elasticsearch
│       │
│       └── Deployment / StatefulSet
│
└── Kibana
        │
        └── Deployment
```

This allows the complete ELK logging pipeline to be tested locally
without requiring managed Kubernetes logging services.

# Example Logging Flow

Suppose an application running inside a Kubernetes Pod generates:

``` text
ERROR: Payment service unavailable
```

The flow would be:

``` text
Application Pod
      │
      ▼
Container Log
      │
      ▼
Filebeat
      │
      │ Adds Kubernetes Metadata
      ▼
Logstash
      │
      │ Parses / Filters Log
      ▼
Elasticsearch
      │
      │ Stores + Indexes
      ▼
Kibana
      │
      ▼
Developer Searches:
"Payment service unavailable"
```

Kibana can then be used to identify:

-   Which Pod generated the error.
-   Which container generated the error.
-   Which namespace contains the Pod.
-   When the error occurred.
-   How frequently the error occurred.
-   Whether similar errors occurred elsewhere.
